### FDR sub-plan (assessment of `multiple_testing_chat_idea.md`)

**DECISION:** use the statistic as a **test statistic with an empirical null + Benjamini–Hochberg**, calibrated on the simulations — *not* the doc's Gaussian/KDE empirical-Bayes pipeline. Concretely: (1) the statistic is **refit ΔBIC** (`log BF ≈ −½·ΔBIC`), no longer the no-refit plug-in predictive density; (2) build the null reference **stratified per (kernel, covariate) pair** (pooling e.g. SE-on-study_days with SE-on-days_from_max is heterogeneous; verified earlier that pooled vs stratified gives realized FDR 0.125±0.11 vs 0.087±0.04 at q=0.10); (3) empirical p-values `p = (1 + #{null ≥ obs})/(1 + B)` → BH at target q, replacing the `1e-4` cutoff and unifying the three code cutoffs (demoted to numerical pre-filter); (4) report realized FDR/FWER vs nominal across SNR settings + sensitivity over q — *this is the evidence Reviewer 2 asked for*; (5) on real iHMP data, get the null by **subject-level permutation**: a single **within-unit circular shift** for every within-unit-varying covariate (no time-column detection needed), **across-unit block permutation** for constant-within-unit covariates, **target permuted with adjusters held fixed** (roles user-supplied). Refit-under-null is committed (needed for the BF interpretation) but note p-value validity only requires identical computation for observed and null. **Validation:** known-null cross-check in simulation (per (kernel, covariate), seed 9102). Fallback if the combined refit×permutation compute is prohibitive: the doc's EB local-fdr, but hardened (half-normal SD factor `1/√(1−2/π)`, Storey π₀, stratified per pair).

The doc's proposal is an Efron-style **two-groups / local-FDR empirical-Bayes** procedure. The *family* is appropriate and one piece is correct (sorting by local fdr and thresholding the cumulative mean = valid global/Bayes FDR). But it needs hardening and must be validated on waveome's own null sims rather than the doc's self-fulfilling mock data.

> **⚠ Major code change — "approximate Bayes factor" requires refitting.** To honestly label the per-component quantity a Bayes factor, the reduced (component-dropped) model must be **refit**, then differenced as ΔBIC (route 3) or refit ΔELBO (route 4). The **refit is the dominant compute cost** — once a reduced model is refit, computing its BIC or ELBO is trivial. Cost scales as (≈ #metabolites × #kernel components) extra penalized fits per model; budget HPC time accordingly and consider caching/warm-starting reduced fits from the full-model parameters. This touches `calc_feature_importance_components` (`utilities.py:613`), which currently drops-and-predicts without refitting. **One implementation, two consumers:** the *same* refit-ΔBIC code path must serve both the simulation (calibration, null piles, realized-FDR table) and the iHMP analysis — they cannot diverge, or the calibration would be for the wrong statistic. Independent of this, **significance/selection** is handled by the empirical-null + BH route, valid under either refit choice, so this decision is about the *evidence/magnitude reporting*, not error control.

> **Caveat — un-normalized NB on continuous data.** The NB PMF re-used on real-valued `y` (via the gamma function) does **not** integrate to 1, so it is an unnormalized *quasi-likelihood*, not a proper density. Consequences: (a) within-likelihood **differences** — ΔBIC, BH selection — are unaffected (the normalizer cancels); (b) the **simulation KL** comparison is unaffected (simulated data are integer counts → NB is a proper PMF there); (c) an **absolute cross-likelihood fit comparison on iHMP** (NB BIC vs log-normal BIC) is **invalid** (different normalization), so it is **omitted** — iHMP likelihood robustness is reported via **selected-metabolite overlap** only. If an absolute NB-vs-log-normal fit claim on real data is ever wanted, normalize the continuous-NB over `[0,∞)` first.
